# Web 端首屏加载优化实践笔记

> 项目：公司核心 SaaS 产品 Web 端
> 作者：前端团队 / 张同学
> 最后更新：2026-03-28

## 背景

我们的 SaaS 产品首屏 TTI（Time To Interactive）长期卡在 4.2s，用户投诉集中在"加载慢"这一点。
目标：把 TTI 降到 2.0s 以内，P95 FCP < 1.5s。

## 现状诊断

使用 Chrome DevTools + Lighthouse 做了一轮完整分析，主要瓶颈：

1. **主 bundle 体积过大**：压缩后仍有 1.8 MB，移动端 4G 下载约 1.5s
2. **首屏依赖的请求串行**：登录态校验 → 用户偏好接口 → 首屏数据接口，串起来 1.2s
3. **图片未用现代格式**：首屏 banner 用的还是 JPG，未启用 WebP/AVIF
4. **第三方脚本阻塞**：埋点 SDK 没异步加载，白屏期间 JS 被阻塞 400ms

性能数据对比见 `assets/性能优化对比图.png`。

## 优化方案

### 1. 代码分割 + 路由级懒加载

- 使用 Vite 的 `import()` 语法按路由切分
- 主 bundle 只保留框架 + 首屏组件，从 1.8 MB 降到 620 KB
- 非首屏路由按需加载，体积外溢控制在可接受范围

### 2. 请求并发化

三个首屏依赖的接口原本串行执行，改造后：

```js
const [auth, prefs, data] = await Promise.all([
  fetchAuth(),
  fetchPrefs(),
  fetchInitialData(),
]);
```

接口侧同步改造了依赖关系（auth 改为 token 本地校验，不必等服务端返回）。

### 3. 图片现代化

- Banner 统一切 WebP + AVIF，size 从 380 KB 降到 95 KB
- 使用 `<picture>` 元素按浏览器支持度回退
- 配合 CDN 的自动格式协商

### 4. 第三方脚本异步化

```html
<script src="analytics.js" async></script>
```

配合 `requestIdleCallback` 延后非关键埋点上报。

## 效果

| 指标 | 优化前 | 优化后 | 目标 |
|------|-------|--------|------|
| TTI | 4.2s | 1.8s | ≤ 2.0s ✓ |
| FCP（P95） | 2.3s | 1.2s | ≤ 1.5s ✓ |
| 主 bundle | 1.8 MB | 0.62 MB | ≤ 1.0 MB ✓ |
| Lighthouse 性能 | 51 | 89 | ≥ 85 ✓ |
