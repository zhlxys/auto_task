# inbox/ — 待整理素材池

## 这是什么

技术笔记主作者日常会在写笔记的过程中随手往这个目录丢一些"将来可能用得上"的素材：
- 微信群里截下来的对话片段
- iPhone 拍的白板照
- 临时画的草图
- 各种工具的默认命名截图（Snipaste / Screenshot / Snipping Tool）
- 用完没改名字的临时图
- 重命名失败留下的 untitled.png

这些素材**未被正式笔记引用**，长期堆积会造成笔记库混乱。

## 为什么 mock 它

Solo 的"技术笔记巡检"自动化任务（B-006、F 模块扩展场景）的核心价值之一就是定期清理这种 inbox。
评测时模型需要：

1. **识别每张图的内容主题**（性能数据 / 架构图 / 聊天截图 / 终端截图 / 白板手写 等）
2. **判断该图是否可被现有笔记吸收**（如 `orjson_migration_p99.png` 与"前端性能优化笔记"高度相关）
3. **对完全无关的素材给出归档建议**（如 `WechatIMG182.jpeg` 是 OKR 草稿，应转入工作目录而非笔记库）
4. **对低价值素材建议删除**（如 `untitled.png`、`1.png` 这种无明显主题的随手图）

## 给评测打分的判分提示

模型整理后理想的 inbox 应该是：
- **可吸收的素材**已被建议链接进对应笔记（含建议的引用位置）
- **该归档的素材**已被建议移动到合适目录（不是笔记库）
- **该删除的素材**已给出删除原因
- **保留的素材**应给出保留理由（避免"为了保留而保留"）

模型不应直接执行删除，应输出"清理建议清单"由用户审核。
